1.1 Lingkup

Pengujian mencakup seluruh permukaan fungsional yang dapat diakses pengguna akhir:

  • Landing page (/) — navigasi, section profil/program/eskul/galeri/fasilitas/tenaga pendidik/kontak, modal PPDB, toggle tema.
  • Autentikasi — /login (guru & siswa), /admin/login (admin), pemeriksaan role, proteksi route, sesi & logout. Gate PIN client-side historis sudah dihapus dari source terbaru.
  • Dashboard Admin (/admin/dashboard) — Ringkasan & analitik, CMS konten (Profil, Hero, Tampilan, Teks Section, Jurusan, Fasilitas, Eskul, Guru, Galeri), Data Siswa/Guru, Kelas, Jadwal, Mapel, Presensi, Pengaturan Ujian, Pesan, Kelola Akun.

  • Dashboard Siswa (/lms/dashboard) — Dashboard, Mata Pelajaran, Jadwal Kelas, Presensi mandiri, Tugas Saya, Ujian/CBT (kode, pengerjaan, anti-curang).

Langkah Reproduksi

  1. Login memakai akun siswa uji resmi dari penyimpanan kredensial terpisah → tab Ujian / CBT.
  2. Klik Masukkan Kode pada ujian UTS → gunakan kode valid yang dibagikan guru di sesi uji privat → Buka Ujian.

Bukti Runtime (ditangkap via error listener)

questions[0].opsi = objek opsi pilihan ganda (butir & jawaban disunting) ← objek, bukan array

Analisis Akar Masalah

API mengembalikan field opsi tiap soal sebagai objek kunci→teks ({A:…, B:…, C:…, D:…}), sedangkan frontend memperlakukannya sebagai array dan memanggil .map(). Objek tidak memiliki metode .map → TypeError tak tertangkap → React 19 meng-unmount seluruh pohon komponen → layar putih. Tidak ada error boundary yang melindungi runner.

Dampak

  • Alur inti CBT lumpuh total: pengerjaan soal, penyimpanan jawaban, timer, submit, dan anti-curang tidak dapat digunakan siswa.
  • Attempt terlanjur dibuat (POST …/attempts → 201, status berjalan); siswa terjebak “SEDANG DIKERJAKAN” dan timer server terus berjalan.
  • Pemulihan hanya melalui refresh manual + “Lanjutkan Ujian” (yang crash lagi) atau reset attempt oleh guru.

3.2 Temuan Keamanan & Cacat Lainnya

HIGH SEC-01 (historis) — PIN Default Admin Studio Terekspos di UI HISTORIS

Temuan historis 21 Nov: UI sebelumnya membocorkan PIN, validasi dan throttle dilakukan di sisi klien, sehingga bukan faktor autentikasi yang aman. Commit 0abebe7 kemudian menghapus gate tersebut; source Admin Studio saat ini tidak lagi memakai PIN sebagai lapisan akses. Ini bukan bukti otorisasi API telah diuji live ulang.

Riwayat: PIN & nilai rahasia DIHAPUS/REDACTED dari salinan laporan ini
Source terkini: tidak ada gate Admin Studio berbasis PIN/sessionStorage
Kontrol yang dinyatakan: token akun + pemeriksaan role admin; perlu uji endpoint berizin

Status: eksposur UI lama ditutup pada source. SEC-01 historis tidak lagi berlaku pada source terbaru, tetapi verifikasi role server, pencabutan token, dan akses API masih belum diuji live (AU-17/19/20, AD-21, SE-09).

MEDIUM BUG-02 — HTTP 500 Intermiten pada API Tugas Siswa TERBUKA

Saat memuat dashboard siswa, console mencatat dua kegagalan GET /api/v1/siswa/assignments?per_page=100&page=1 → 500. Permintaan ulang manual beberapa menit kemudian mengembalikan 200 dengan data valid. Indikasi ketidakstabilan backend (cold-start/timeout Wasmer Edge).

Dampak: daftar tugas siswa dapat gagal tampil sesaat. Retest 21 Nov: kedua pemuatan 200 — tidak tereproduksi. Sejak commit 0abebe7, client API terbaru menerapkan timeout 20 dtk dan retry GET terbatas (0,5/1,5 dtk) untuk network/429/5xx; perubahan tersedia di source lokal tetapi perilaku produksi belum diverifikasi ulang. Tetap perlu memastikan komponen menampilkan error/retry yang dapat dipahami, bukan hanya empty-state.

MEDIUM BUG-03 — Roster Presensi Guru Tidak Konsisten dengan Data Admin FIXED

Tab Presensi guru untuk X DKV 1 menampilkan “0 siswa — Belum ada siswa di kelas ini. Hubungi admin untuk mendaftarkan siswa ke X DKV 1.”, padahal menu Kelas admin mencatat 5 siswa (Siswa 2, 4, 6, 8, 10) dan Data Siswa 10 siswa aktif. Guru tidak dapat mempresensi kelas itu.

Perbaikan: endpoint baru GET /guru/classes/{schoolClass}/students (routes/api.php:135 → DashboardController::teacherClassStudents, guard 403 bila kelas tidak diampu); DashboardGuru.jsx:281–293 mengambil roster resmi per kelas ampu. Retest 21 Nov: Presensi X DKV 1 → 5 siswa (Siswa 10, 2, 4, 6, 8); X TKJ 1 → 5 siswa; Rekap Nilai X DKV 1 5 (dulu 0), X TKJ 1 5 (dulu 1) → GU-04 LULUS.

LOW / INFO OBS-01 · OBS-02 · OBS-03 — Observasi Minor MASIH TERBUKA

  • OBS-01: retest mengonfirmasi — pada t=60ms & 200ms header “(0 data)” + “0 dari 0 siswa” tampil bersama skeleton; terisi “(10 data)” di t≈700ms. Skeleton hanya mengganti badan tabel, bukan hitungan header.
  • OBS-02: Retest: login admin 5,5 dtk redirect + 7,1 dtk render; login siswa >11 dtk. Cold-start ini juga pemicu BUG-04.
  • OBS-03: kedua warning deprecated Rive masih muncul di console build index-BSD_wKoR.js:350; kosmetik.

6.1 BUG-04 (BARU) — Overlay Fallback Menutupi Aplikasi yang Sehat

MEDIUM Layar putih “Aplikasi gagal dimuat” padahal aplikasi berfungsi

Gejala: setelah reload pada cold-start, pengguna melihat layar putih penuh bertuliskan “Aplikasi gagal dimuat / Tidak ada pesan error yang tertangkap”, padahal dashboard dan lembar ujian sudah ter-render normal di baliknya. Kasus SI-17 gagal karena ini.

#root.children.length = 2 (aplikasi React + box fallback)
box.style = position:fixed; inset:0; z-index:99999; background:#fff
getBoundingClientRect → 624 × 610 (seluruh viewport)
document.elementFromPoint(tengah layar) === box → true
document.visibilityState = hidden · console error = 0

Akar masalah: watchdog di index.html:34–47 menyuntikkan box fallback ke dalam #root bila root.children.length === 0 setelah 5 detik, dan tidak pernah menghapusnya. Karena cold-start backend/frontend melebihi 5 detik (OBS-02: login 5,5–11 dtk), watchdog terlanjur menyuntik box; React kemudian mount sebagai sibling, sehingga box tetap menutupi aplikasi. Ini menjelaskan gejala “Aplikasi gagal dimuat” pada laporan awal — dulu bertumpang tindih dengan crash BUG-01, kini berdiri sendiri.

Rekomendasi: hapus box saat React selesai mount (MutationObserver pada #root, atau cek ulang berkala dan box.remove() bila root sudah punya child lain); atau naikkan ambang waktu di atas cold-start terukur; atau render fallback di luar #root dan sembunyikan begitu aplikasi siap. Tambahkan uji reload pada koneksi lambat.
